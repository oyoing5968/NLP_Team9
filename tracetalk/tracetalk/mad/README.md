# 해석: MAD와 결과 카드 (mad)

댓글 하나를 받아 표현마다 결과 카드를 만든다. 같은 4B 모델이 근거를 달리 받은 에이전트로 나뉘어 서로 묻고 답하고, 판정자가 고른다.

| 에이전트 | 보는 것 | 하는 일 |
|---|---|---|
| A · DB 근거 | DB의 뜻 | 뜻 후보를 낸다 |
| B · 근거 글 | 그 말을 다룬 뉴스레터 글(댓글은 안 봄) | 글에서 읽은 뜻을 낸다. E가 반박하면 고치거나 물러난다 |
| C · 가린 문맥 | 표현을 가린 댓글 | 문장 상황과 이 자리의 뜻. 근거가 없을 때 문맥으로 해석한다 |
| D · 반대 근거 | 고른 뜻과 "글자 그대로" | 글자 그대로 쓴 것 아니냐고 반박한다. 뜻을 낸 쪽은 댓글의 단서로 답하거나 인정한다 |
| E · 검증 | 근거 글의 문장 후보 | B의 뜻을 받치는 문장을 고른다. 못 찾으면 그 뜻은 확인 필요로만 보인다 |
| 판정 | 모든 보기 | 보기 순서를 돌려 가며 한 토큰으로 물은 확률 |

| 파일 | 하는 일 |
|---|---|
| `card.py` | 결과 카드 전체: 탐지, 에이전트, 토론(`debate_select`, `defend_use`), 판정(`verdict`), 쉬운 표현, 문장 해석. 설정은 맨 위 `CARD` |
| `engine.py` | 모델 호출과 기록의 바탕(`Analyzer`), 0.4~0.6의 옛 비교 방식(시험과 비교 실험용, 화면에는 없음) |
| `contracts.py` | 모델 답의 JSON 형식과 검사 |
| `benchmark.py` | 시험 입력 읽기 |

## 주요 설정 (`CARD`)

| 키 | 0.13 기본 | 뜻 |
|---|---|---|
| `debate` | `True` | 에이전트끼리 묻고 답함 (끄면 0.11) |
| `debate_mode` | `select` | E가 근거 문장을 후보 중에서 고름 (`quote`: B가 베껴 옴, 개발에서 나빴음) |
| `tau_support` | 0.9 | E가 받아들이는 문턱 |
| `mad_first` | `True` | 모든 낱말에 B·C, 근거가 없으면 C가 문맥으로 해석 |
| `min_context` | 3 | 표현 밖 글자가 이보다 적으면 C도 짐작하지 않음(0.12.1, "쮀쮀이야"). 같은 기준으로 낱말만 넣은 말은 DB·근거 글의 뜻을 지우지 않고 '확인 필요'로(0.13) |
| `tau_easy_blank` | 0.5 | 4B가 처음부터 쓴 쉬운 표현은 확인 점수가 이것을 넘어야 씀(한 번 더 써 보고도 못 넘으면 비우고 문장은 원문대로, 0.13 "여행") |
| `contrast`, `tau_contrast_check`, `tau_contrast_literal`, `tau_concede` | 켬, 0.15, 0.7, 0.5 | D의 반대 근거와 문턱 |

개발 세트 216문장(출처를 가린 채점): 토론 없음 맞음 151 · 확정 오답 23 → 0.12 맞음 152 · 확정 오답 20 → 0.13 맞음 153 · 20(낱말만 규칙이 닿는
한 문장만 다시 돌림). 설계와 근거: `docs/DESIGN.md`.
