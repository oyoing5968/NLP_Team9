# 크롤러: 설계, 보안, 측정

새 신조어는 상용 AI와 사전에 오르기 전에 신조어 뉴스레터에 먼저 실린다. 크롤러는 그 글을 받아 근거 글(카드가 읽는 자료)로 넣고, 뽑은 낱말·뜻은
사람이 검수할 표로 만든다. 모델이나 화면이 부르지 않는, 사람이 직접 치는 명령이다.

## 경계

- 시연 화면·서버(`tracetalk/web/run.py`)와 모델은 인터넷을 쓰지 않는다(이 컴퓨터 안 127.0.0.1에서만).
- 받는 곳은 허용 목록 `data/crawl/sources.txt`뿐이다: maily.so/trendaword, maily.so/farmingletter, gogumafarm.kr, letter.wepick.kr.
  바꿀 때는 팀이 합의하고 한 줄씩.
- 받은 원문은 `_crawl/`, 근거 글은 `data/db/live/corpus.jsonl`. 둘 다 git에 올리지 않는다(.gitignore, 각 뉴스레터의 저작물).

## 두 단계

1. **받기 (인터넷):** 허용 목록의 주소만 받아 원문 파일로 저장한다. 해석·실행·압축 해제 없음. 파일마다 보안 점검(`tracetalk/crawl/audit.py`).
2. **넣기 (인터넷 없음):** 점검을 통과한 글의 글자만 근거 글로 넣는다(`tracetalk/db/update.py corpus-add`). 낱말·뜻 후보는 팀 표(CSV)로만 나오고, DB에는
   사람이 고른 행만 들어간다(`tracetalk/db/update.py import`, 확인했으면 `--reviewed`).

## 위협과 막는 법

| 위협 | 막는 법 |
|---|---|
| 허용 안 된 곳에 접속, 리다이렉트로 다른 곳 | 허용 목록의 호스트·경로와 정확히 같을 때만, https만. 리다이렉트도 같은 검사(3번까지). 주소를 먼저 찾아 사설·로컬·링크 로컬·멀티캐스트·예약 주소면 거부하고 확인한 그 주소로만 연결, 인증서는 호스트 이름으로 검사 |
| 큰 응답, 끝없는 응답 | 응답 2 MB, 요청당 20초, 요청 사이 5초. robots.txt를 지킨다 |
| 위험한 파일 | text/html·xml만. 저장 이름은 주소의 해시(경로 조작 불가). 받은 것을 실행하지 않음. 실행 파일·압축·PDF 거부 |
| XML 폭탄 | DOCTYPE·ENTITY 선언이 있으면 거부, 크기 상한 |
| 새 패키지(공급망) | 크롤러는 표준 라이브러리(urllib·html.parser·json·xml.etree)만 쓴다 |
| 글 속에 숨긴 명령(프롬프트 주입) | 받은 글은 모델에 '자료' 칸으로만 들어가고 모델에는 도구가 없다(출력은 정해진 JSON 하나). 뜻 200자·용례 120자 상한, 제어 문자·HTML 태그·주소 제거 |
| 화면 공격(XSS) | 화면은 textContent만 쓰고 innerHTML 0, CSP는 'self'만, 서버는 127.0.0.1에만 열림, 출처 주소는 글자로만 보임 |
| DB 오염(틀린 뜻·억지 유행·광고) | 새 뜻은 "검수 전"으로 추가만. 있는 행은 고치거나 지우지 않음. 행마다 출처 주소·가져온 날짜. 카드는 검수 전 행을 MAD로 검증 |
| 팀 표의 수식 공격 | 칸 첫 글자 = + - @ 제거, 제어 문자·태그 거부 |
| 개인정보 | 용례에서 @아이디·메일·전화번호를 지움 |
| 저작권·약관 | 근거 글은 이 컴퓨터 안에서만 근거로 쓰고, 카드에는 짧은 인용과 주소만. 저장소에는 주소 목록만 싣고 원문은 각자 다시 받는다(`mac/fetch_corpus.sh`). 나무위키·커뮤니티·SNS 긁기는 하지 않음 |

## 샌드박스 (macOS가 강제)

`mac/run.sh`가 모든 명령을 `mac/sandbox/*.sb` 안에서 돌린다.

| 규칙 | 무엇을 | 읽기·쓰기 | 네트워크 |
|---|---|---|---|
| `app.sb` | 도구, 시연 화면, 시험 | 이 폴더와 `_mac_runtime`만 | 이 컴퓨터 안(localhost)만, 바깥 주소 묻기(DNS)도 막음 |
| `ollama.sb` | Ollama | 같음 | 이 컴퓨터 안만, DNS도 막음(Ollama가 켜질 때 ollama.com에 붙으려는 시도는 이름 묻기에서 끝남). `OLLAMA_NO_CLOUD=1` |
| `crawl.sb` | 크롤러 받기 단계 | 읽기는 이 폴더, 쓰기는 `_crawl/`만 | https(443) 밖으로만, 화면·Ollama에는 못 붙음 |

확인: `bash mac/sandbox_check.sh`(상위 폴더 읽기·쓰기, 시스템 임시 폴더, 바깥 인터넷, 바깥 주소 묻기(DNS), 크롤러의 DB 쓰기 등을 일부러 시도해 막히는지 봄).
한계: `sandbox-exec`는 애플이 구식으로 분류한 도구다. 사이트 이름 단위로는 못 막아서 사이트 목록은 코드가 맡는다.

## 뽑기 측정 (낱말·뜻을 자동으로 뽑아 DB에 넣을 수 있는가)

기준은 측정 전에 적음: ① 정밀도(뽑힌 뜻 행이 실제 신조어·밈이고 뜻이 그 글의 풀이와 맞음) 80% 이상 ② 재현(정답표 낱말 중 뜻까지 맞게 뽑힌 것)
70% 이상 ③ 안전(행 안의 주소·아이디·전화번호·스크립트, 목록 밖 행) 0. 정답표는 웹만 쓰는 하위 에이전트가 코드를 보지 않고 만들었다.

| 방법 | 세트 | ① 정밀도 | ② 재현 | ③ 안전 |
|---|---|---|---|---|
| v1 규칙 | 세트 1 확인 절반(17글) | 21% | 35% | 0 |
| v2 사이트별 규칙 | 세트 2(새 글 20) | 50% | 10% | 0 |
| v3 4B가 읽고 뽑기 | 세트 2 | 76% | 67% | 0 |
| v3 4B가 읽고 뽑기 | 세트 3(새 글 24) | 48% | 51% | 0 |

받기·점검·격리는 설계대로 동작했다(받기 79/79, 점검 79/79, 안전 0). 뽑기는 기준에 못 미쳤다: 4B가 브랜드·사람 이름·행사를 신조어로 뽑고, 글 대신
제 지식으로 뜻을 쓰는 일이 있었다(비하 표현도 그대로 뽑음). 그래서 **자동으로 DB에 넣지 않고, 사람이 표를 보고 고르는 반자동만 쓴다.** 0.9부터는
뽑기 대신 글 전체를 근거 글로 넣고, 카드가 문장마다 그 글을 읽는다.

## 쓰는 법

```
bash mac/fetch_corpus.sh          # 이 저장소의 시연·시험이 읽은 글 96개를 다시 받아 근거 글로 (처음 한 번)
bash mac/crawl_new.sh             # 허용 목록 사이트의 목록 페이지에서 아직 없는 새 글을 찾아 받고 근거 글에 더함
bash mac/crawl.sh <주소 목록>      # 받기 + 점검 + 낱말 표(검수용 CSV) 만들기
```
