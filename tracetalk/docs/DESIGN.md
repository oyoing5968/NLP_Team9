# 설계 (TraceTalk 0.10)

결과는 `docs/RESULTS.md`, 크롤러와 보안은 `docs/CRAWLER.md`, 팀 모듈 규격은 `docs/API_CONTRACT.md`·`docs/TEAM_MODULE.md`.
코드 주석의 "DESIGN.md"는 이 문서(버전별 설계 기록을 하나로 줄인 것)를 가리킨다.

## 흐름 (팀 발표자료 6쪽)

```
문장 입력
 → 신조어·유행어 탐지: DB 표기·변형(exact) · 형태소 기본형(morph, kiwipiepy) · 자모 오타(fuzzy, RapidFuzz)
                       · 근거 글이 인용한 구절 · 근거 글의 표제어(v13) · 형태소 분석기가 모르는 명사
                       · (DB에서 찾은 게 없고 신조어 같으면) 모델이 한 부분을 고름
 → 관련 용례 검색: 그 표현의 용례를 지금 댓글과 가까운 순서로(bge-m3 임베딩 + ChromaDB)
 → 문맥 기반 의미 해석 (MAD): 근거별 에이전트 → 판정
 → 쉬운 표현 및 설명: DB의 쉬운 표현(팀 > 교사 초안 > 모델) · 댓글 전체를 쉬운 말로 다시 쓴 문장(검사 후)
 → 결과 카드: 뜻 · 쉬운 표현 · 문장 해석 · 관련 용례 · 유래 · 근거(DB 출처·검수 여부·날짜, 근거 글 주소·날짜·인용 문장)
              · 에이전트별 답과 판정 확률 · 뜻 확인 필요 / 뜻 모름 표시
```

코드: 탐지와 카드 `tracetalk/mad/card.py`, DB 검색 `tracetalk/db/retriever.py`·`tracetalk/db/lexicon.py`, 용례·DB 갱신 `tracetalk/db/usage.py`·`tracetalk/db/update.py`,
근거 글 `tracetalk/evidence/corpus.py`·`tracetalk/evidence/reading.py`, 화면 `tracetalk/web/run.py`·`tracetalk/web/server.py`·`tracetalk/web/static/`.

## MAD (근거별 에이전트와 판정, 0.9~)

발표자료 7쪽의 "LLM A·B·C 토론 → 후보 비교 → 최종 결정"을 4B에 맞게 바꾼 것이다. 에이전트는 **같은 4B 모델**이고, 각자 다른 근거만 받는다.

| 에이전트 | 보는 것 | 내는 것 |
|---|---|---|
| A · DB 근거 | DB의 뜻(들), 검수 여부 | 보기: DB 뜻 C1, C2 … |
| B · 근거 글 | 그 낱말이 나온 뉴스레터 글 조각(댓글은 안 봄) | 보기: 글에서 읽은 뜻 R1 (DB 뜻과 닮으면(0.65 이상) "받쳐 줌") |
| C · 가린 문맥 | 표현을 가린 댓글 | 문장 상황 → DB 뜻이 여럿일 때 가장 닮은 뜻 (v16 MAD 우선: 모든 낱말, 근거가 없을 때 문맥으로 짐작한 뜻) |
| D · 반대 근거 (v15) | 고른 뜻과 "글자 그대로"만 | 글자 그대로 쪽 몫 (v16: 뜻을 낸 에이전트에게 반박) |
| E · 검증 (v16) | B가 인용한 글의 한 부분만 | 그 부분이 그 뜻을 말하는가 |
| 판정 | 위의 보기 + "표준어 그대로(L)" + "맞는 뜻 없음(N)" | 보기 순서를 돌려 가며 한 토큰으로 물어 확률(모든 회전의 평균) |

판정 규칙(`tracetalk/mad/card.py` `verdict`, 문턱은 개발 세트 fresh_v1~v3에서 정함):

| 경우 | 결과 |
|---|---|
| 표준어(L)가 앞서고 몫 ≥ 0.7 (`tau_literal`, v13) | 표준어: 카드에서 뺌 |
| 표준어가 앞서지만 0.7 미만 | 뜻 확인 필요(유력한 뜻을 보임) |
| 맞는 뜻 없음(N)이 앞섬 | 뜻 확인 필요, 뜻을 쓰지 않음. 단 글이 적어 둔 풀이(R1)가 있으면 그 풀이를 확인 필요로 보임(v13) |
| 표준어 몫 ≥ 0.2 (`tau_plain`) | 뜻 확인 필요 |
| 글에서 읽은 뜻이 DB보다 앞섬 | 몫 ≥ 0.5면 확정, 아니면 확인 필요 |
| 검수된 DB 뜻이거나 글이 받쳐 줌 | 몫 ≥ 0.5면 확정 (`tau_reviewed`) |
| 검수 전 DB 뜻 | 몫 ≥ 0.9면 확정 (`tau_sure`), 그 직전에 4B에게 그 행을 보여 주고 반대하면 확인 필요 |
| 오타 단계로 맞춘 DB 행 | 확정하지 않음(v13) |
| DB에도 글에도 없음 | 뜻 모름 · 수집 목록에 적음(지어내지 않음) |

뜻은 **근거의 문구 그대로**(DB 행 또는 글에서 읽은 뜻)를 쓴다. 4B가 다시 쓰게 하면 뜻이 망가졌다(개발: "음식이 나를 바라보는 구도" →
"음식이 보이는 구도"). 문맥은 문장 해석이 맡는다. 확인 필요인 뜻은 쉬운 표현과 문장을 "이 뜻이 맞다면"으로만 보인다(`easy_if`, `sentence_if`).

### 토론 (v16, `debate`)

에이전트끼리 묻고 답한다. 따지는 쪽은 말로 다투지 않고 **근거 글의 문장**으로 확인한다. 예전에 입장을 맡겨 자유롭게 토론시켰을 때는
나빠졌고(92문장 68 대 75) 토론자가 원문을 인용한 적이 297번 중 0번이었다.

| 주고받기 | 묻는 쪽 → 답하는 쪽 | 어떻게 | 결과 |
|---|---|---|---|
| 근거 검증 | E → B | 코드가 근거 글에서 그 낱말을 다룬 문장 후보(최대 4개)를 뽑고, E가 "B의 뜻을 말하는 문장"을 후보와 "없음" 가운데서 고른다(보기 순서를 돌려 가며) | 받침(1 − 없음 몫) 0.9 이상이면 그 문장을 인용으로 붙여 받아들임(`tau_support`). 아니면 E가 반박하고, B가 후보 문장을 다시 읽어 뜻을 한 번 고치거나 물러남. 고친 뜻은 E가 다시 봄. 끝내 받쳐지지 않은 뜻은 지우지 않고 확인 필요로만 보임 |
| 반대 근거 | D → 고른 뜻을 낸 A나 B | 댓글에서 단서를 대어 방어 / 인정 | D 몫 0.15 이상일 때만. 단서가 있으면 D가 단서를 보고 다시 묻고 그 몫을 씀. 인정했고 D 몫이 0.5 이상이면 글자 그대로 |
| 서로 받침 | A와 B가 같은 뜻(닮음 0.65 이상) | — | 따로 따지지 않음 |

글이 적어 둔 풀이(괄호·쌍점 등, 아래 '근거 글 읽기')는 규칙으로 찾은 것이라 E가 바로 받아들인다. 화면에는 주고받은 차례가 그대로 나온다.
B가 글의 문장을 베껴 오게 한 판(`debate_mode: "quote"`)은 4B가 글을 글자 그대로 옮기지 못해 맞는 뜻까지 물러나 개발에서 나빴다(맞음 151 → 142).
기록으로 코드에 남겼고 기본은 고르기(`select`)다. 4B 검증자는 맞는 읽기와 틀린 읽기를 충분히 가르지 못해서, 검증에 실패한 뜻을 지우지 않고 낮추기만 한다.

### MAD 우선 (v16, `mad_first`)

DB가 답을 혼자 정하지 않게 한다. 검수된 DB 낱말에도 B가 근거 글을 읽고, 모든 낱말에서 C가 문맥을 읽어 토론 기록에 주장으로 들어간다.
DB와 근거 글에 아무것도 없거나 B가 물러나면, C가 낱말을 가리고 읽은 문장 속 뜻을 "문맥으로 짐작한 뜻 (근거 없음)"으로 낱말 뜻과 나눠 보인다.
짐작은 확정하지 않고 쉬운 표현과 문장 해석에 넣지 않는다(근거 없이 쓴 뜻은 개발에서 26개 중 2개만 맞았다).

표현을 가리면 읽을 것이 남지 않는 댓글(표현 밖 글자 3개 미만, `min_context`, 0.12.1)에서는 C도 짐작하지 않고 '뜻 모름'이다
("쮀쮀이야"는 '이야'만 남아, 4B가 "현재의 상황이나을 의미하는 말"처럼 내용 없는 짐작을 냈다).

토론과 MAD 우선은 개발 세트로 켰다(기준은 실행 전에 적음, 결과는 `docs/RESULTS.md` 5).

### 낱말만 넣었을 때 (v18, 0.13)

낱말 하나만 넣는 것은 그 말의 새 뜻을 묻는 것으로 본다. DB나 근거 글에 뜻이 있으면, 판정이 '글자 그대로'(오디세이 → 호메로스의 작품)로 기울어도
지우지 않고 그 뜻을 '확인 필요'로 보인다("문맥이 없어 가릴 수 없다"). 아무것도 찾지 못한 낱말은 '신조어 없음'으로 넘기지 않고 새 말인지 물어
'뜻 모름'으로 보인다(그래야 수집 목록과 자동 업데이트로 이어진다). 앞뒤에 말이 있는 문장은 그대로다.

### 쉬운 표현 확인 (v18)

DB·팀·교사 초안에 쉬운 표현이 없어 4B가 처음부터 쓴 쉬운 표현은 뜻과 맞는지 묻고, 아니면 한 번 더 쓰게 한 뒤에도 50%를 못 넘으면 비운다
(오디세이를 근거 글대로 '오늘 디저트 세 개 이상 먹은 것'으로 읽고도 쉬운 표현을 '여행'으로 써 "오늘 완전 여행네"가 됨). 그때 문장 해석은 그 말을
원문 그대로 둔다. 팀과 교사가 쓴 쉬운 표현은 예전처럼 지우지 않는다.

### 자동 업데이트 (v18, 기본은 꺼짐)

질문은 노트북 안에서만 풀고, 근거 글만 밖에서 받는다. `bash mac/start.sh --auto-update`가 켤 때·6시간마다·모르는 말을 만난 뒤(30분에 한 번까지)
`mac/crawl_new.sh`를 돌린다: 허용 목록 뉴스레터의 새 글 → 점검 → 근거 글(화면은 다음 카드부터 읽음), 새 말 후보 → 검수 대기열. 모르는 말은 보내지
않고 `data/db/live/update_wanted` 표시만 남는다. 11-11 이 맥에서 한 번 돌림: 새 글 12개 받음·점검 통과 12, 근거 글 96 → 106, 검수 후보 9(그중
'오디세이'의 뜻을 다른 낱말에 붙인 것이 있어, 자동으로 DB에 넣지 않는 이유가 그대로 보임).

## 근거 글 읽기 (0.9, 0.10에서 고침)

- 근거 글: 허용한 신조어 뉴스레터 네 곳(트렌드어워드, 파밍레터, 고구마팜, 위픽레터; 사이트 세 곳)의 글. `tracetalk/evidence/corpus.py`가 그 낱말이 나온 글 조각을 점수로
  고른다(점수 1.5 미만은 이름만 나온 것으로 보고 읽지 않음, `tau_passage`).
- **글이 적어 둔 풀이를 먼저** (`tracetalk/evidence/reading.py`, v13): 괄호 "치올(치고 올라간다)", 쌍점 "손절미: …", "~하는 걸 X라고 해", "~를 'X'로 표현",
  잘못 들린 가사, "X란". 있으면 그 풀이가 뜻이 되고 그 문장이 카드에 인용된다. 영문 머리글자의 괄호(GMG(가면 감))는 풀이로 보지 않는다.
  그 낱말을 이름으로 가진 문장이 모두 더 긴 다른 낱말(손절 ← 손절미)이나 다른 낱말의 풀이이면 그 글은 읽지 않는다.
- 풀이 문장이 없으면 4B가 글 조각 전체를 요약한다(0.9). 유래도 읽되, 따옴표·로마자로 쓴 이름이 글에 없으면 유래를 비운다(지어낸 이름 방지).

## DB

- 행: 표현·변형·뜻·유래·품사·쉬운 표현·출처·검수 여부(검수됨/검수 전)·넣은 날짜. 용례 묶음은 따로.
- 처음 DB: KoCulture(CC BY-NC-SA 4.0)에서 만든 시연 사전 495항목과 용례(`data/db/lexicon`, `data/db/usage`), 교사 모델이 쓴 쉬운 표현 초안
  (`easy_draft_v2.jsonl`, 카드에 "교사 초안 · 검수 전"으로 표시).
- 시연 DB `data/db/live/`: 팀 발표자료의 예시(긁히다)와 뉴스레터에서 정리한 66행(`data/demo/demo_db_v13.csv`), 모두 검수 전.
- `tracetalk/db/update.py`로 넣으면 화면을 켠 채로 바로 반영된다. 사람이 확인한 행은 `--reviewed`.
- 수집기: 카드가 만난 DB에 없는 말을 `data/db/live/candidates.jsonl`에 쌓고, 같은 말이 다른 문장에 두 번 이상 나오면 그 문장들을 용례로 삼아 다음 카드가
  뜻을 추정한다('추정' 표시). `tracetalk/db/update.py queue`가 검수용 표를 만든다.

## 학습 모델

학생 v1: Qwen3.5-4B(대화용 후처리 모델; 모델 파일의 기반 표기 'Base'는 그 모델 설명서가 적은 상위 모델명)에 LoRA(rank 16, alpha 32) 지도 학습. 학습 자료는 KoCulture 학습 분할 문장에 대해 더 큰 교사 모델이 쓴 답 가운데 채점을 통과한
것(`eval/export_sft.py`). GPU 한 장에서 한 번 학습(`eval/train_lora.py`, 2 epoch, lr 1e-4), 합친 뒤 Q4_K_M GGUF로 바꿔 Ollama로 돌린다
(`model/README.md`). 시험·검증·학습 분할은 낱말 가족이 겹치지 않는다(`data/eval/eval_v1`).
