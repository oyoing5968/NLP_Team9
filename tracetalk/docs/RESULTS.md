# 결과 (TraceTalk 0.10~0.12)

잰 것만 적는다. 모든 기준은 시험을 돌리기 전에 적었고, 결과를 본 뒤 바꾸지 않았다. 답별 판정은 `eval/results/*.csv`에 있다(카드 실행 기록 원본은
뉴스레터 글 조각을 담고 있어 이 저장소에 넣지 않았다).

## 채점 방법

- **출처를 가린 표.** 같은 문장에 대한 여러 시스템(TraceTalk 여러 설정, Gemini)의 답을 섞어 a), b) …로만 보인다. 같은 글자의 답은 한 줄로 합친다.
- **채점자 둘이 따로, 갈린 표시는 셋째.** 채점자는 출처를 모르는 AI 채점자(Claude 하위 에이전트)다. 채점표 파일 하나만 읽고 결과 파일 하나만
  쓴다. 사람 검수는 아직 없다.
- 뜻: 참조의 핵심(무엇을 가리키는 말인지)을 전하면 o, 다른 뜻이거나 틀린 사실을 덧붙이면 x, 그 댓글의 다른 표현을 풀이하면 d.
  유래: 정답과 같은 출처(사이트·영상·작품·사람·계정)를 대면 o, 다른 출처나 틀린 사실이면 x, 말하지 않으면 n.
- **결과 규칙:** 맞음 = 뜻 o(뜻 확인 필요로 보였어도), 확정 오답 = 뜻 x이면서 확정('확실')으로 보임, 나머지 보류. 신조어가 없는 문장(B·P)은
  표준어로 둔 것도 맞음.
- 두 채점자 일치: fresh_v4 뜻 482표시 98.1%(카파 0.93), 유래 290표시 93.4%(0.87). fresh_v5 뜻 30/31·36/36, 유래 36/36·36/36.
- 정답표와 시험 문장은 개발 중에 정리했고 팀 검수 전이다. 문장은 뉴스레터의 실제 용례를 쓸 수 있는 곳은 그대로 쓰고 나머지는 AI(Claude)가 글의
  용례 투로 썼다.

**0.10에서 고친 것** (자세히는 `docs/DESIGN.md`)

1. 근거 글이 정해진 꼴로 적은 풀이를 뜻으로 쓰고 그 문장을 인용한다(근거 글 읽기, 개발 84낱말: 0.9 61 맞음·23 틀림 → 65·18). 문장 번호를 붙여

2. 근거 글의 표제어(트렌드어워드 '오늘의 단어', 밈 모음의 제목)가 댓글에 나오면 DB에 없어도 후보로 올린다.
3. 물결표·대소문자(L~을 가져가), 영문 머리글자 괄호는 풀이로 보지 않음(GMG(가면 감)), 쉬운 말이 원문 어미와 겹치는 문장 오류.
4. 판정에 DB 용례를 보여 주기: 해 보고 껐다(표준어 문장 5개가 밈으로 확정됨).
5. 표준어 판정은 몫이 0.7 이상일 때만 낱말을 뺀다(개발: 표준어 쓰임 0.88~1.00, 신조어 쓰임 0.40~0.63).
6. 뜻 확인 필요인 DB 뜻의 쉬운 표현과 그 문장을 "이 뜻이 맞다면"으로만 보인다(발표자료 6쪽 예시).
7. 글이 적어 둔 풀이는 '맞는 뜻 없음'이 앞서도 뜻 확인 필요로 보인다(지우지 않음).
8. 오타 단계로 맞춘 DB 행은 확정하지 않는다(저메추 → DB의 점메추).

## 5. 0.12: 에이전트가 서로 따지는 MAD (개발 세트, 2026-11-10, 성적 아님)

0.11까지의 MAD는 에이전트마다 다른 근거를 주고 판정자가 고르는 방식이라, 에이전트끼리 말을 주고받지 않았다. 0.12에서는 에이전트가 서로 따진다.

| 주고받기 | 무엇 |
|---|---|
| C의 첫 말 | 모든 낱말에서 C가 표현을 가린 댓글로 이 자리의 뜻을 읽어 먼저 낸다. 근거가 없는 낱말은 C의 읽기를 "문맥으로 짐작, 확인 필요"로만 보인다 |
| B → E | B가 근거 글에서 읽은 뜻을 내면, E가 그 뜻을 말하는 문장을 근거 글의 문장 후보 가운데서 고른다(보기 순서를 돌려 가며 묻고, "없음"도 보기). 받침 0.9 이상이면 그 문장을 인용으로 붙여 받아들인다 |
| E → B | 받치는 문장이 없으면 E가 반박하고, B는 뜻을 한 번 고치거나 물러난다. 고친 뜻은 E가 다시 본다 |
| 끝내 확인 못 함 | 그 뜻을 지우지 않고 "확인 필요"로만 보인다. 4B 검증자의 잡음이 맞는 뜻을 지우지 않게 하려는 것이다 |
| D → A·B | 고른 뜻이 "글자 그대로"일 수 있으면(몫 0.15 이상) D가 반박하고, 뜻을 낸 쪽은 댓글에서 단서를 대거나 인정한다 |

**미리 적은 규칙** (각 판을 채점하기 전): 토론 판이 토론 없는 판(같은 코드에서 토론만 끔)보다 확정 오답이 많지 않고 맞음이 3개 넘게 줄지 않으면
기본으로 켠다. 맞음이 같거나 많으면 '나아짐'으로 적는다.

| 216문장 (fresh_v2+v3+v4), 출처를 가린 채점 | 맞음 | 확정 오답 | 문장당 시간 (가장 김) |
|---|---|---|---|
| 토론 없음 | 151 | 23 | 21.3초 (74.6초) |
| 토론 1: B가 글의 문장을 베껴 오고 E가 확인 | 142 | 20 | 19.5초 (58.6초) |
| **토론 2: E가 문장 후보에서 고름 + 모든 낱말에 B·C (0.12 기본)** | **152** | **20** | 24.4초 (86.0초) |

- 토론 1은 맞음이 9개 줄어 켜지 않았다. 4B가 글의 문장을 글자 그대로 옮기지 못해(한두 글자 틀림, 자기 뜻을 다시 씀, 빈 인용) 맞는 뜻까지
  물러났다. 그래서 토론 2는 문장 찾기를 코드가 하고(그 낱말을 다룬 대목의 문장) 4B는 고르기만 한다. 토론 2는 토론 1의 결과를 보고 고친 판이라
  개발 점수다. 깨끗한 확인은 마지막 새 시험에서 한다.
- 토론 없음에서 토론 2로 바뀐 9문장: 좋아짐 7(왜요쌤 2·잇엇은·나니가스키: 확정 오답 → 확인 필요, E가 받치는 문장을 못 찾음; 뇌절·젬민이: 보류 →
  맞음, C의 문맥 읽기; 불미스러운 일: 보류 → 맞음), 나빠짐 2(띠로리: 근거 글이 이름이 같은 다른 밈을 다뤄 판정이 그쪽을 고름; 이건 첫번째 레슨:
  D의 반박을 인정해 표준어로 봄).
- 주고받은 횟수(216문장): C 읽기 211, B 주장 179(DB 뜻과 같아 따지지 않음 65, E가 받아들임 85, E가 반박 29), 반박받은 B는 29번 모두 물러났고 그 뜻은
  지우지 않고 확인 필요로 남았다. D의 반박 15번은 모두 인정됐다.
- 4B의 한계: B가 반박을 받고 뜻을 고친 적은 없고, D의 반박에 단서를 댄 적도 없다. 토론의 몫은 주로 "근거 글로 받쳐지지 않는 뜻을 확정하지 않는
  것"(확정 오답 23 → 20)과 C의 문맥 읽기(맞음 +2)에서 나왔다. 문장당 3초쯤 느려졌다.
- 0.12.1(같은 날): 표현을 가리면 읽을 것이 남지 않는 댓글(표현 밖 글자 3개 미만)에서는 C도 짐작하지 않는다. 시연 문장 "쮀쮀이야"에서 4B가
  "현재의 상황이나을 의미하는 말"이라는 내용 없는 짐작을 냈기 때문이다. 개발 실행의 짐작 6개는 모두 표현 밖 글자가 6개 이상이라 개발 점수는
  그대로이고, 시연 12문장을 다시 돌리니 이 문장만 '뜻 모름'으로 바뀌고 나머지 11장은 같았다.

## 8. 정리

- **성능은 상용 AI보다 낮다.** 뜻 전체(73 대 112), 새로 생긴 말(11 대 18) 모두 Gemini가 앞섰다.
- **발표에서 의도한 기능은 모두 동작한다**: 탐지 → 관련 용례 검색 → 문맥 기반 의미 해석(MAD) → 쉬운 표현 및 설명, 그리고 DB(의미·유래·품사)와
  근거 글, 맥에서 인터넷 없이.
- **가장 큰 병목은 4B가 근거 글을 읽는 실력이다.** 더 큰 모델(7.8B)은 같은 글을 조금 더 잘 읽었다(47개 중 36 대 32). 모델이 크면 나아질 여지가
  있다. 다만 더 큰 모델로 카드 전체를 재 보지는 않았다.
- **0.12의 토론은 작게 나아졌다**(개발 216문장 맞음 151 → 152, 확정 오답 23 → 20). 에이전트가 근거로 서로 따지고, 받쳐지지 않는 뜻은 확정하지
  않는다. 개발 점수이므로 마지막 새 시험에서 다시 잰다.
- 남는 차이: 근거에 있는 것만 말하고(지어낸 유래 4/40, 0/5) 근거가 없으면 확정하지 않으며('뜻 모름', 0.12는 문맥으로 짐작한 뜻을 '확인 필요'로만),
  근거 글의 주소·날짜·인용과 에이전트가 주고받은 말을 보이고, 대화를 밖으로 보내지 않는다.
